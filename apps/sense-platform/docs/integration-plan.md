# خطة التكامل المعمارية لـ SENSE

## القرار المعتمد

تُعد **Sense Store** مصدر الحقيقة التجاري للمنتجات والأسعار والمخزون والـ Checkout. تستخدم منصة SENSE طبقة Storefront المهيأة في المشروع لعرض الكتالوج وإنشاء السلة وإحالة العميل إلى Checkout، ولا تخزن بيانات البطاقة ولا تعيد بناء كتالوج Shopify في قاعدة البيانات المحلية.

يظل **Senseivo** موقع الهوية والفريق والمحتوى المؤسسي. يرتبط بالمنصة عبر روابط واضحة وهوية بصرية مشتركة، لكنه لا يصبح لوحة تشغيل أو مصدرًا لحالات البلاغات والطلبات. مسارات التشغيل والحسابات والصلاحيات تبقى داخل SENSE.

## حدود التكامل الحالية

| المجال | مصدر الحقيقة | ما تنفذه SENSE | الحالة |
|---|---|---|---|
| المنتجات والأسعار والصور | Shopify Storefront | عرض الكتالوج والسلة والـ Checkout | موصول |
| إحالة Checkout | قاعدة SENSE + رابط Shopify | حفظ userId وcheckout reference دون بيانات دفع | موصول |
| الدفع والشحن وحالة التنفيذ | Shopify Admin/Webhooks | لا تعرض SENSE حالة نهائية قبل تفعيل مصدر موثوق | معلّق |
| الهوية المؤسسية | Senseivo | رابط وهوية مشتركة وصفحات معلومات | قرار معماري |
| البلاغات والصلاحيات | قاعدة SENSE | tRPC وحواجز الأدوار وسجل الأحداث | موصول جزئيًا ومختبر |

## خطوات الربط أو الترحيل

1. تثبيت ملكية متجر Shopify وقناة النشر، ثم التحقق من أن المنتجات المطلوبة منشورة ومصورة ومُسعرة فعليًا.
2. الاحتفاظ بمعرّفات Shopify الأصلية عند الحاجة إلى المطابقة، وعدم إنشاء نسخة محلية تنافس Shopify في السعر أو المخزون.
3. عند الحاجة إلى حالة الطلب، تفعيل Webhook موثوق من Shopify Admin إلى endpoint خادمي موثق، والتحقق من التوقيع، ثم حفظ أقل قدر من حالة الطلب المرتبطة بإحالة checkout.
4. إجراء اختبار قبول يشمل إنشاء الطلب، تغير حالة التنفيذ، الإلغاء أو الاسترداد، وعزل بيانات المستخدمين قبل عرض أي حالة في `/orders`.
5. إبقاء Senseivo طبقة محتوى مستقلة مع روابط إلى المنصة، وعدم نقل أسرار أو بيانات تشغيلية إلى الموقع المؤسسي.

## ما لا يُنفذ تلقائيًا

لا تُرحّل بيانات المتجر أو تُنشأ طلبات أو تُعرض حالات دفع وشحن تقديرية دون موافقة المالك وتفعيل مصدر Shopify موثوق. لا تُستخدم بيانات تجريبية على أنها مبيعات أو مراجعات حقيقية.
